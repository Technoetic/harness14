# v4.2.1 — harness14 plugin identity

The public repository, plugin name and marketplace identity are now `harness14`.
The canonical start commands are `/harness14:webapp` for Claude Code and
`$harness14:webapp` for Codex. Codex's native status/reset skills are
`harness14-status` and `harness14-reset`.

The namespace is recognized by the explicit-start and control-prompt parsers.
Installed-cache protection also covers the new name. Existing input aliases remain
recognized; host plugin namespaces are not automatically installed aliases.

Disable the prior `harness20` identity in the same scopes before enabling the new
one. Preserve per-project disabled settings, previous caches and other plugins.
Open a new host session to discover the new native skill catalog. Review changed
hook definitions through the host's existing manual trust procedure.

Workflow state, receipts, archived instruction bodies, profile IDs, environment
report markers and the shared Jev usage ledger keep their existing paths and
contracts. This release does not renumber or initialize existing runs.

The fourteen-step default and optional offline trials introduced in v4.2.0 remain.
The current README includes the implemented paper/project attribution mapping and
the current MoAI-ADK project URL.

Validation results and installation observations accompany the release assets.
Tests of temporary fixtures and installed files do not establish a real model-run
or business-performance outcome.
